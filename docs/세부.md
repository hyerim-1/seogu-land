# 세부페이지 설계서: 기획안 소개 페이지 (`architecture.html`)

![대전 서구 브랜드 이미지 — SEOGU 글자 안에 나무, 주민, 집이 그려진 일러스트](../images/seogu-logo.jpg)

- 작성일: 2026-09-16
- 기획자: 서구청 토지정보과 윤혜림
- 대상: [「우리동네 국·공유재산」 랜딩 페이지](https://seogu-land.vercel.app)에 추가할 첫 번째 세부페이지

## 1. 왜 만드나

랜딩 페이지는 "무엇을 만들 것인가"를 보여준다. 이 세부페이지는 그 다음 질문에 답한다.

> **이 시스템을 어떤 계획으로 만들 것이고, 설계는 어떤 형식으로 되어 있는가?**

지금은 그 내용이 `docs/기획-설계서.md`와 `docs/구현-계획서.md` 안에만 있어서, 랜딩 페이지를 본 사람은 볼 수 없다. 이를 **시스템 구조도 한 장**으로 꺼내 보여준다.

## 2. 페이지 구성 (위 → 아래)

1. **머리말** — 제목 「이 서비스는 이렇게 만들어집니다」, 한 줄 설명, "기획안" 배지, 서구 브랜드 이미지
2. **기획의도 「왜 이걸 만드나」** — 민원과 정책지원 두 갈래 (이 문서 2-1장)
3. **시스템 구조도** — 데이터가 왼쪽에서 오른쪽으로 흐르는 4칸 (이 문서 4장)
4. **외부 데이터 목록** — 어느 시스템에서 무엇을 받아오는지 표 + 확인하면서 드러난 것 (이 문서 3장)
5. **하단** — 랜딩으로 돌아가기 + 기존 고지 문구

배포 주소는 `https://seogu-land.vercel.app/architecture`. `vercel.json`에 `cleanUrls`를 켜서 확장자 없이 열리게 한다.

### 2-1. 기획의도

두 갈래를 나란히 둔다. 한쪽만 쓰면 "민원 편의 서비스" 하나로만 읽혀서, 이 일의 절반이 가려진다.

| | 민원 | 정책지원 |
|---|---|---|
| 누가 | 주민·민원인 | 구청 담당 부서 |
| 지금 문제 | 국유재산포털, 대전광역시 재산정보 공개시스템, 서구 사전정보공개, 토지이음을 차례로 돌아야 하고 신청은 방문 | 「우리 구에 국·공유재산이 어디에 얼마나 있나」를 보려면 대장을 엑셀로 받아 직접 세어야 함 |
| 이 서비스 | 필지 하나 화면으로 합쳐 보여주고 온라인 신청·결과 알림 | **지도 위에 소유 구분대로 칠해, 세지 않고 보게 함** |
| 쓰임새 | 방문 민원 감소, 처리 기간 단축 | 유휴재산 찾기, 활용 계획 수립, 대부료 세입 근거, 편중 확인, 재산관리관 확인으로 부서 간 조율 |

정책지원 쪽에는 이번에 실제 자료를 붙여 보고 바로 드러난 숫자를 근거로 싣는다.
도마동 구유 446건 / 둔산동 구유 32건 / 월평동 시유 263건 / 지금 빌릴 수 있는 시유 55건 —
**도심은 시유, 외곽은 구유로 갈린다.** 표로 6,015줄을 볼 때는 안 보이던 것이다.

## 3. 외부 데이터 연계 검토 (2026-09-16 확인)

구조도의 "외부 데이터" 칸에 넣을 시스템을 실제로 열어 확인한 결과다.

### 3-1. 국유재산

| 항목 | 내용 |
|---|---|
| 시스템명 | **e나라재산 국유재산포털** 지도서비스 |
| 운영 | 기획재정부 |
| 주소 | https://www.k-pis.go.kr/addMapView.do |
| 제공 | 일반재산, 매각대상, **대부대상**, 사용중인재산, 매각제한대상 / 용도지역도·용도지구도·행정구역도·도로명지도 |
| 연계 방식 | 화면은 링크로 연결. 대부 가능 재산 목록은 공공데이터포털 **[한국자산관리공사_국유재산특례 운용현황(대부) 조회서비스](https://www.data.go.kr/data/15126820/openapi.do?recommendDataYn=Y)** 오픈API(JSON/XML)로 받음 |
| 판정 | **연계 가능** |

국유재산포털이 "모든부동산검색 기능은 **브이월드(V-World)의 Open API**를 활용하여 제공합니다"라고 밝히고 있다. 우리 서비스도 지도 배경과 지적 경계는 같은 방식(브이월드)으로 가져오면 된다.

### 3-2. 시유재산

| 항목 | 내용 |
|---|---|
| 시스템명 | **대전광역시 재산정보 공개시스템** |
| 운영 | 대전광역시 회계과 재산관리담당 (042-270-4651~3) |
| 주소 | https://www.daejeon.go.kr/jaesan/PropertyList.do |
| 규모 | 2026년 4월 기준 **38,589건** |
| 항목 | 재산번호, 구분, 소재지, 재산관리관, 지목, 실면적(㎡), 회계기준가액(원) |
| 검색 | 소재지(구별), 소유자 구분, 재산종류, 회계구분, 재산관리관, 지목, 대장가액, 면적, 취득기간, **대부정보** |
| 판정 | **연계 가능** |

**시유재산과 구유재산이 한 시스템에 함께** 들어 있고 "소유자 구분"으로 나뉜다. 우리 서비스의 국유/시유/구유 3색 구분과 그대로 맞는다. 서구 자료만 받으려면 소재지에서 서구를 고르면 된다.

### 3-3. 구유재산

| 항목 | 내용 |
|---|---|
| 출처 | **대전 서구 사전정보공개** 게시판 —「유휴 공유재산 공개 목록('26.5월말 기준)」 |
| 작성 | **서구청 토지정보과** (2026-05-27) |
| 첨부 | 구유재산·시유재산 XLSX 2개 (대전 서구 소재) |
| 이용조건 | 공공누리 **제4유형** — 출처표시 + 상업적 이용금지 + **변경금지** |
| 판정 | **연계 가능하되, 내부 대장을 직접 연계할 것** |

공개 파일이 공공누리 4유형(변경금지)이라 **파일을 가공해 서비스 화면에 올리는 방식은 적절하지 않다.** 대신 이 자료를 만드는 부서가 토지정보과 자신이므로, 공개 파일을 긁어오지 말고 **구청 내부 공유재산 대장(원본)을 직접 연계**한다. 그러면 갱신 주기도 월 1회 게시 → 실시간으로 개선된다.

### 3-4. 함께 쓰는 데이터

| 시스템명 | 운영 | 받아올 것 |
|---|---|---|
| **브이월드(V-World) 공간정보 오픈플랫폼** | 국토교통부 | 배경지도, 항공영상, 연속지적도(필지 경계) |
| **토지이음** | 국토교통부 | 토지이용계획(용도지역·지구·구역) — 화면 수집 없이 열람 링크 + 공개 API |
| **문자 알림 서비스** | 구청 기존 계약 | 접수·허가·반려 결과 안내 |

## 4. 시스템 구조도

데이터가 **왼쪽에서 오른쪽으로 흘러갔다가 되돌아오는** 형태로 그린다.

```
  ① 이용자              ② 화면                ③ 우리 서비스              ④ 외부 데이터
 ┌──────────┐      ┌──────────────┐      ┌────────────────┐      ┌────────────────────────────┐
 │          │ 지번  │              │ 조회  │                │ 재산  │ e나라재산 국유재산포털      │
 │ 주민·    │ 검색  │  재산 조회   │ 요청  │  재산 정보     │ 자료  │  (기획재정부) — 국유       │
 │ 민원인   │─────▶│  서류 신청   │─────▶│  모아서 보여줌 │─────▶│                            │
 │          │      │  도면 보기   │      │                │      │ 대전광역시 재산정보        │
 │ 구청     │      │              │      │  신청서 접수·  │      │  공개시스템 — 시유·구유    │
 │ 담당자   │◀─────│  접수함      │◀─────│  처리 상태     │◀─────│                            │
 │          │ 처리  │  검토 화면   │ 필지  │                │ 필지  │ 서구 공유재산 대장(내부)   │
 └──────────┘ 결과  └──────────────┘ 정보  │  재산대장 DB   │ 정보  │                            │
                ⑤                    ②     │  신청서 DB     │  ④   │ 브이월드 — 지도·지적도     │
                                            └────────────────┘      │ 토지이음 — 토지이용계획    │
                                                    │               │ 문자 알림 서비스           │
                                                    └──── ③ ───────▶└────────────────────────────┘
                                                        신청 결과를
                                                        대장에 반영
```

**웹 화면에서는 이 그림을 인라인 SVG가 아니라 HTML 박스 + CSS Grid로 만든다.** 첫 화면 지도와 달리 구조도는 글자가 주인공이라, 이렇게 해야
- 화면을 줄이면 **가로 4칸 → 세로 4칸**으로 자연스럽게 바뀌고,
- 글자 확대·스크린리더에서도 그대로 읽히며,
- 문구를 고칠 때 SVG 좌표를 다시 계산하지 않아도 된다.

## 5. 흐름 5단계

| | 단계 | 내용 |
|---|---|---|
| ① | **찾는다** | 주민이 지번이나 동 이름으로 검색한다. |
| ② | **모아서 보여준다** | 서비스가 국유(e나라재산·공공데이터포털), 시유·구유(대전광역시 재산정보 공개시스템, 서구 내부 대장), 경계·항공영상(브이월드), 용도지역(토지이음)을 한 카드로 합쳐 보여준다. **이용자는 네 곳을 각각 돌아다니지 않는다 — 이것이 이 서비스의 핵심이다.** |
| ③ | **신청한다** | 사용(대부)허가 신청서, 매수신청서, 사용(대부)허가 포기서를 화면에서 작성해 제출하면 신청서 DB에 쌓인다. |
| ④ | **검토한다** | 담당자가 신청서와 해당 필지 정보(사용·대부 현황, 용도지역, 지적도·위치도·현황도)를 **한 화면에서** 보고 허가 또는 반려한다. |
| ⑤ | **되돌려 준다** | 결과가 문자와 화면으로 신청인에게 가고, 동시에 재산대장과 「활용 가능 재산현황」 목록이 자동으로 갱신된다. |

## 6. 만드는 방식

| 파일 | 작업 |
|---|---|
| `architecture.html` | 새로 만듦 |
| `style.css` | 기획안 페이지용 규칙을 파일 끝에 추가 |
| `index.html` | 상단 메뉴와 「개발 계획」 섹션에 링크 추가, 첫 화면 지도 설명·출처 갱신 |
| `script.js` | 첫 화면 지도가 실제 재산 건수를 읽도록 변경 |
| `data/seogu-jaesan.json` | 수집한 동별 건수와 활용 가능 시유재산 55건 |
| `images/seogu-logo.jpg` | 서구 브랜드 이미지 (12.8KB) — 머리말에 사용 |
| `vercel.json` | `cleanUrls`를 켜서 `/architecture`로 열리게 함 |

### 첫 화면 지도에 실제 자료를 붙인 방법

1. 대전광역시 재산정보 공개시스템에서 **소재지 서구 + 소유자 구분**으로 검색해 법정동 27곳의 건수를 받음
2. 법정동을 지도의 행정동 23곳에 맞춤(둔산동 → 둔산1·2·3동, 서구 남부 법정동 → 기성동 등). **표시용 근사**임을 데이터 파일에 적어 둠
3. 행정동마다 **50건당 표시 하나**를 뿌림. 색은 랜딩과 같게 국유 초록 / 시유 노랑 / 구유 파랑
4. 빗금은 "그 동에 지금 빌릴 수 있는 시유재산이 있다"는 뜻으로 **동마다 하나만**.
   2,415건 중 미대부가 55건뿐이라, 건수에 비례시키면 오히려 부풀려 보인다
5. 국유(초록)는 연계 전이라 드론이 조사하는 세 곳만 예시로 남김

**클래스 이름 주의.** 랜딩이 이미 `.dot`과 `.steps`를 쓰고 있어서, 기획안 페이지 것은
`.owner-dot`처럼 따로 이름을 붙였다. 같은 이름을 쓰면 랜딩의 범례가 깨진다.

- 색·글꼴·상단바·버튼·하단은 **기존 토큰과 마크업을 그대로 재사용**한다. 따로 디자인하지 않는다.
- `script.js`는 **불러오지 않는다.** 첫 화면 지도와 데모 전용이라 이 페이지에는 쓸 곳이 없고, 붙이면 콘솔 오류만 난다.
- 빌드 없음. `architecture.html`을 브라우저로 바로 열 수 있어야 한다.
- 머리말의 서구 브랜드 이미지는 `alt`에 그림 내용을 적고, 폭이 좁아지면 함께 줄어들도록 `max-width: 100%`를 준다. 출처는 대전광역시 서구로 표기한다.

## 7. 확인 방법

- `architecture.html`을 열어 기획의도 두 칸과 구조도 4칸이 모두 보이는지
- **375px 폭**에서 세로 4칸으로 쌓이고 가로 스크롤이 없는지
- 콘솔 오류 없음
- 랜딩 → 기획안 페이지 → 랜딩으로 왕복되는지
- 외부 시스템 링크 4개가 새 창으로 열리는지
- 배포 후 `https://seogu-land.vercel.app/architecture`에서 동일하게 동작하는지
- 랜딩의 범례(`.dot`)와 이용 흐름(`.steps`)이 그대로인지
